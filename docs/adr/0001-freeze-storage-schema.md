# 冻结阅读进度与跳转意图的存储 schema

用户既有的 `p:<书键>`、`progress` 整包、`po:<地址>`、单值 `pendingOpen` 数据不迁移、不改名。新逻辑一律经 `NR.progress` / `NR.intent` 模块读写，并继续兼容读取旧格式。代价是模块内保留迁移与兼容分支，收益是升级不丢阅读进度、多标签页语义保持不变。

遗留键名沿用历史拼写（冻结，不随领域术语改名）：`progress`（旧整包）、`pendingOpen`（旧单值跳转标记）、`blacklist`（站点停用列表）。未消费的跳转意图没有定时清理器，最长残留到 TTL 之后的第一次 boot（由 `NR.intent.consume` 顺带清扫）。

## Considered Options

- **一次性迁移旧数据后只留新格式**：被否。读写并存才覆盖得住「升级后未重新打开的标签页」；一次性迁移半途失败就是永久丢进度。
- **把键名改成领域术语（如 `pausedSite`）**：被否。存储键是跨版本契约，改名等于新旧版本互相看不见对方的数据。
